# Template Usage Order - Clear Workflow

## The Standard Path (Recommended for Most Users)

### Phase 1: Start with Starter Template (Week 1)
**File:** `starter-template.md`

**What to do:**
1. Read through the starter template
2. Fill in the 5 essential sections:
   - Context
   - Constraints
   - Goals
   - Preferences
   - Red Flags
3. Copy your filled sections to Claude Project → Custom Instructions
4. Use for one week
5. Notice friction (what needs correcting repeatedly)

**Why starter first:**
- Minimal setup (15-30 minutes)
- Works immediately
- You can't anticipate needs before using it
- Examples show you the pattern (Health/Fitness domain)

**Don't look at Advanced Template yet** - you don't know what you need.

---

### Phase 2: Capture Friction (Week 2-3)
**Still using:** Your filled starter template

**What to do:**
1. Use Claude normally with your starter setup
2. When you correct Claude 3+ times for the same thing:
   - Create a memory instruction (using template in starter)
   - Add to Project Memory (not Custom Instructions)
3. Track patterns you notice

**The Rule of Three:**
- 1st correction: Note it
- 2nd correction: Pattern maybe?
- 3rd correction: Definitely a pattern → capture it

**Tools you're using:**
- Starter template (in Custom Instructions)
- Memory instructions (in Project Memory)
- Friction log (mental or written notes)

---

### Phase 3: First Expansion (Month 1)
**Now you might look at:** `advanced-template.md`

**What to do:**
1. Review the "What to Add Next" section in starter template
2. Based on your friction, identify 1-2 sections you actually need
3. Open advanced template as a **reference**
4. Look at the specific section you need (e.g., Operating Modes)
5. Adapt that section to your needs
6. Add to your Custom Instructions

**Example:**
"I notice I ask planning questions differently than execution questions. Let me check the Operating Modes section in the advanced template."

**Don't:**
- Copy the entire advanced template
- Add sections "just in case"
- Fill in everything at once

**Do:**
- Add ONE section at a time
- Use it for a week to see if it helps
- Only add more if friction reveals need

---

### Phase 4: Continuous Evolution (Ongoing)
**Using:** Starter base + selected advanced sections + memory instructions

**Monthly review:**
1. What's working? (keep it)
2. What causes friction? (fix it)
3. Has context changed? (update it)
4. Need new advanced sections? (add one)

**The templates are tools, not destinations**

---

## Alternative Paths

### Path A: "I've Used Claude Projects Before"
**Start:** Starter template
**Why:** Even experienced users benefit from structured friction-driven approach
**Skip to:** Phase 3 faster (after 1 week instead of 1 month)

### Path B: "I Have Complex Needs Already"
**Start:** Starter template
**Also read:** Advanced template to see what's possible
**Why:** Still fill starter first, but you'll know what to add after Week 1
**Timeline:** Phase 1 → Phase 3 (skip Phase 2 delay)

### Path C: "I Just Want to See Examples"
**Read:** Example files (health-fitness or career-coding)
**Then:** Start with starter template
**Why:** Examples show the end result, but you still need to fill your own

## What Each Template Actually Is

### Starter Template = Your Launch Pad
- **Purpose:** Get working system in 15-30 minutes
- **When to use:** Always start here
- **What's in it:** 
  - 5 core sections (blank templates)
  - 1 example per section (Health/Fitness)
  - Appendices with other domain examples
  - Guidance on what to add next
- **Think of it as:** Minimum viable setup

### Advanced Template = Your Reference Library
- **Purpose:** See all possible expansions
- **When to use:** After Week 1, when friction reveals needs
- **What's in it:**
  - All optional sections (8 different expansions)
  - 1 example per section (Career/Coding)
  - Appendices with other domain examples
  - Guidance on when to use each section
- **Think of it as:** Menu of options, not a to-do list

---

## Common Mistakes to Avoid

❌ **Starting with Advanced Template**
- Too overwhelming
- You don't know what you need yet
- Wastes time on sections you won't use

❌ **Filling in Entire Advanced Template**
- Takes hours
- Most sections won't be relevant
- Over-specification creates rigidity

❌ **Never Expanding Beyond Starter**
- Misses opportunities for improvement
- Friction persists that could be fixed
- Not using system's full potential

✅ **The Right Approach:**
1. Start minimal (starter)
2. Notice friction (weeks 1-3)
3. Add deliberately (one section at a time from advanced)
4. Evolve continuously (monthly reviews)

## Quick Decision Tree

**Q: I'm starting a new Claude Project. Which template?**
A: Starter template. Always.

**Q: I've used my starter setup for a week. Now what?**
A: Did you notice friction patterns?
- Yes → Check "What to Add Next" section, possibly look at advanced template
- No → Keep using, wait for friction

**Q: I know I need Operating Modes. Where do I find that?**
A: Advanced template. Read just that section, adapt to your needs, add to your setup.

**Q: Should I read both templates before starting?**
A: Skim both to understand the system, but only fill in starter.

**Q: Can I skip starter and just use advanced?**
A: You can, but you'll likely over-engineer and waste time on sections you don't need.

**Q: How do I know when I need an advanced section?**
A: When you experience friction 3+ times that section would solve.

- **Week 1:** Use it, notice friction
- **Week 2-3:** Add memory instructions for patterns (3+ occurrences)
- **Month 1:** Review friction, add 1-2 advanced sections if needed
- **Monthly:** Review and refine
- **Ongoing:** Evolve based on real use

## The Core Principle

**You cannot anticipate what you'll need before experiencing friction.**

That's why:
- Starter gets you working quickly
- Advanced provides options when you discover needs
- Memory captures patterns from real use
- Evolution happens through practice, not planning

**Trust the process:**
1. Start minimal
2. Notice friction
3. Add what addresses it
4. Repeat

The templates support this process, they don't replace it.
