# Quick Start Checklist

Use this checklist to set up your first Claude Project with custom instructions.

---

## ☑️ Pre-Setup (5 minutes)

- [ ] Decide which project domain to start with (health, career, writing, etc.)
- [ ] Open the relevant example in `/examples/` for reference
- [ ] Have a Claude Project ready (or create new one)
- [ ] Block 30 minutes of focused time

---

## ☑️ Phase 1: Core Setup (15 minutes)

### Core Identity & Context
- [ ] **Who I Am:** Describe your role and relevant background (3-5 sentences)
- [ ] **What I'm Trying to Achieve:** List 3-5 concrete goals
- [ ] **Current Challenges:** Note real obstacles you're facing

### Quick Reference Summary
- [ ] **One-line project description:** Capture essence in one sentence
- [ ] **Primary goal:** The single most important objective
- [ ] **Key constraint:** The biggest limitation
- [ ] **Success looks like:** What achieving this means in practice

---

## ☑️ Phase 2: Communication Setup (10 minutes)

### Communication Preferences
- [ ] **Tone & Style:** How do you want Claude to communicate?
- [ ] **Response Structure:** Preferred format (bullets vs. prose)
- [ ] **Language:** British/American English? Technical level?

### Operating Modes (Choose 2-3 to start)
- [ ] **Mode 1:** _______________ (e.g., Strategic Planning)
  - When to use: ______________
  - How Claude should respond: ______________
  
- [ ] **Mode 2:** _______________ (e.g., Tactical Execution)
  - When to use: ______________
  - How Claude should respond: ______________

---

## ☑️ Phase 3: Domain Specifics (10 minutes)

### Key Principles (5-7 core principles)
- [ ] Principle 1: ______________
- [ ] Principle 2: ______________
- [ ] Principle 3: ______________
- [ ] Principle 4: ______________
- [ ] Principle 5: ______________

### Success Metrics
- [ ] **Primary metric 1:** ______________ (how measured)
- [ ] **Primary metric 2:** ______________ (how measured)
- [ ] **Primary metric 3:** ______________ (how measured)

---

## ☑️ Implementation (5 minutes)

- [ ] Copy your completed template
- [ ] Open Claude Project → Settings → Custom Instructions
- [ ] Paste the custom instructions
- [ ] Save changes
- [ ] Test with a typical question for your domain

---

## ☑️ Testing & Validation (5 minutes)

### Test Questions (Ask these in your new project)
- [ ] **Test 1:** Ask a typical question in your domain
- [ ] **Test 2:** Trigger a specific operating mode
- [ ] **Test 3:** Request something that tests your key principles

### Validation Checks
- [ ] Does Claude acknowledge your context?
- [ ] Are responses at the right skill/detail level?
- [ ] Does the tone match your preferences?
- [ ] Are responses actionable and relevant?

**If something feels off:** Note it for Week 1 review, don't worry about perfecting yet.

---

## ☑️ Week 1: Usage & Friction Tracking (Daily, 2 min)

### Daily Practice
- [ ] **Day 1:** Use project normally, note any friction
- [ ] **Day 2:** Use project normally, note patterns in friction
- [ ] **Day 3:** Use project normally, identify recurring issues
- [ ] **Day 4:** Use project normally, continue tracking
- [ ] **Day 5:** Use project normally, prepare for weekly review

### Friction Log Template
```
Date: ______________
What I asked: ______________
Claude's response: ______________ (or summary)
What I corrected: ______________
Why it needed correction: ______________
Pattern? (Yes/No/Maybe): ______________
```

---

## ☑️ Week 1 Review (15 minutes)

### Review Questions
- [ ] What worked well? (Keep this)
- [ ] What caused friction? (Fix this)
- [ ] What patterns appeared? (Add to memory)
- [ ] What was unclear? (Clarify in system prompt)
- [ ] What was missing? (Add to system prompt)

### First Memory Instructions
- [ ] Review friction log for patterns (3+ occurrences)
- [ ] Use friction-detection prompt: "Looking at our conversations this week, what patterns do you see in my corrections?"
- [ ] Create 1-3 memory instructions from identified patterns
- [ ] Add to project memory (Settings → Memory)
- [ ] Test if friction is resolved

---

## ☑️ Month 1 Maintenance (30 minutes monthly)

### Monthly Review Checklist
- [ ] Review all conversations from past month
- [ ] Identify new friction patterns
- [ ] Update system prompt for changed context
- [ ] Add new memory instructions (2-5 new ones)
- [ ] Remove or consolidate obsolete memory
- [ ] Test changes with typical questions
- [ ] Update version and changelog

### Key Questions
- [ ] Has my situation changed? (goals, constraints, context)
- [ ] Are my principles still accurate?
- [ ] Do my operating modes still match usage?
- [ ] Are communication preferences still right?
- [ ] Do success metrics still make sense?

---

## ☑️ Common Friction Patterns to Watch

### Response Style Issues
- [ ] Too formal / too casual
- [ ] Too long / too brief
- [ ] Too many bullet points / not enough structure
- [ ] Too technical / too simplified

### Context Issues
- [ ] Claude assumes wrong skill level
- [ ] Ignores specific constraints
- [ ] Suggests things I can't do
- [ ] Doesn't reference past context

### Content Issues
- [ ] Generic advice (could apply to anyone)
- [ ] Missing domain-specific knowledge
- [ ] Wrong priorities or decision framework
- [ ] Doesn't follow key principles

---

## ☑️ Troubleshooting Quick Fixes

### "Responses are too generic"
→ Add more specific context to "Who I Am" and "Current Challenges"

### "Claude assumes wrong skill level"
→ Explicitly state skill level and give examples of what you can/can't do

### "Style doesn't match my preferences"
→ Add specific examples of good vs. bad response styles

### "Claude suggests impossible things"
→ Be more explicit about constraints in "Context & Constraints"

### "Operating modes feel the same"
→ Make response style differences more dramatic with contrasting examples

---

## ☑️ Success Indicators

After 1 week, you should notice:
- [ ] Less need to explain basic context
- [ ] Responses feel more relevant to your situation
- [ ] Fewer generic suggestions
- [ ] Better alignment with your communication style
- [ ] Claude references your goals and constraints naturally

After 1 month, you should experience:
- [ ] Significantly reduced friction on common tasks
- [ ] 3-5 solid memory instructions working consistently
- [ ] Confidence in the core system prompt structure
- [ ] Clear understanding of what works for you
- [ ] Project feels like a collaboration, not just a tool

---

## ☑️ Next Steps

### After Successful First Project
- [ ] Apply learnings to second project domain
- [ ] Share patterns that worked with community
- [ ] Explore advanced features (framework docs, complex memory)
- [ ] Consider multi-project coordination if relevant

### Continuous Improvement
- [ ] Weekly: Quick friction check (5 min)
- [ ] Monthly: Full review and updates (30 min)
- [ ] Quarterly: Deep review and restructure if needed (1 hour)
